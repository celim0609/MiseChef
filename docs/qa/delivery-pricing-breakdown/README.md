## Related Production time investigation (Phase 1, read-only)

MC-1125-UQXH was created 25 November 2026 at 10:59:50 MYT and paid at 11:04:26 MYT. All five accepted fulfilments and parent schedule store 09:00. Store delivery settings last changed 15 November: delivery 09:00–18:00, Monday–Friday, 1-day lead time, 14-day horizon, Asia/Kuala_Lumpur. Delivery uses minute-resolution time inputs, not pickup session slots; the saved pickup session does not constrain delivery. Both 09:00 and 11:00 pass delivery validation.

Deployed Production source initializes general delivery time to deliveryHours.from. Daily values take precedence via deliveryDays[date]?.time || deliveryTime. General input changes only deliveryTime; closing checkout resets deliveryTime but does not clear deliveryDays. Reusing per-date overrides can therefore submit 09:00 even when the general input shows 11:00. This is a confirmed state consistency defect, but browser actions for this particular purchase are unavailable.

The backend validates every canonical schedule entry, makes each quote with that entry's date/time, binds the canonical schedule to the snapshot hash, and rechecks that binding at payment preparation. The source-derived provider schedule for stored 09:00 MYT is 01:00Z on each service date; 11:00 MYT would be 03:00Z. Raw provider request bodies and scheduleAt are not retained in quote snapshots or available invocation logs, so those outbound timestamps are reconstruction, not recovered request payloads. No evidence establishes that 11:00 was submitted and rewritten to 09:00.

Store draft sessionStorage retains cart/contact/payment choices, not delivery time. Checkout close/reopen in the same mounted page retains per-date state; a full page reload restores the general default 09:00. Final customer messages read canonical fulfilments and format the saved wall-clock time directly as 9:00 AM; there is no timezone conversion causing a two-hour shift. The evidence proves accepted/stored 09:00, not an explicit customer selection of 09:00. Phase 3 addresses state integrity without editing this paid order.
