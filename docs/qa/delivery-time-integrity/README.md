# Delivery Hours and checkout time integrity (Phase 3)

Separate from Phase 2 pricing disclosure. No existing orders or pricing snapshots are migrated. Fixed buffer arithmetic and booking/payment/cancellation workflows are unchanged.

- Reuse the independent `delivery.fulfilment.preOrder.deliveryHours` settings and clarify earliest/latest delivery labels. Store Opening Hours and Pickup Hours remain independent. Existing Owner/Manager Store Settings permissions apply.
- Public checkout requires an explicit time. Slot choices run every 15 minutes from the configured earliest time and include the exact latest endpoint. Backend continues to accept any valid minute inside the configured range for compatible clients; both frontend and backend use the same clock/range policy. Invalid or reversed ranges fail closed.
- General time changes remove all daily time overrides, retaining per-date addresses. Previously overridden times can only be restored through an explicit confirmation. New per-date edits invalidate override confirmation, block quoting/payment until confirmed, and are labelled in the final per-date summary.
- Close/restart and Store reload reset general time, daily times, addresses and override confirmation together. Delivery times are not restored from cart sessionStorage.
- Quotations and payment use the same resolved daily fulfilments. Checkout controls and Close are locked while payment preparation is in flight so the displayed schedule cannot change underneath the accepted request. Each new per-day quote snapshot additionally records local time, actual outbound `requestedScheduleAt` and request-recorded timestamp. Existing snapshots are untouched. Server validates every date/time before retrieving payment quotes, and retains the existing schedule binding so changes require a refreshed quotation.
- Authenticated Owner/Manager Add Order continues to support special arrangements including school deliveries outside delivery hours. Existing server-side transactional role verification supplies authority, never client flags. Other operators cannot bypass configured hours for store-arranged manual deliveries. Saved draft, creator and remarks provide the existing audit record.
- Order Details and WhatsApp continue to read canonical saved fulfilments; Malaysia 11:00 maps to 03:00Z in provider requests and formats as 11:00 AM in messages. No historical fulfilment is rewritten.

Validation: TypeScript; 489 Store tests; 131 focused Functions pricing, delivery, fulfilment, manual-order and POS-quote tests. Added reducer regressions cover single/multi/five-day selection, stale overrides, explicit preservation, confirmation invalidation, checkout reopening, per-day address retention and WhatsApp schedule consistency. Provider test doubles verify each outbound schedule, payment binding and rejection before provider lookup; manual tests verify Owner/Manager school arrangements and denial of forged Chef authority. A 390px browser fixture using the actual shared controls/projection verified general time propagation, explicit restore, reset and compact pricing layout without calling Firebase, payment or Lalamove APIs.

Rollback: revert this commit independently while retaining Phase 2. Future snapshots only add audit fields, which older code safely ignores.
